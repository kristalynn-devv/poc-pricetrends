# poc-pricetrends

Point the tool at a Thai secondary-market listing page. It takes a screenshot with Playwright,
sends the image to Gemini, and gets back structured product data shaped by a per-category
template.

A proof of concept for price tracking, where the input is a rendered page rather than an API.

## Why a screenshot

These sites have no API, and their markup changes without warning. A scraper built on selectors
breaks quietly and keeps returning plausible-looking nonsense. A screenshot plus a schema-bound
extraction fails loudly instead, and survives a redesign.

## Layout

pnpm workspace monorepo, no Python anywhere:

| Workspace | What it is |
| --- | --- |
| `apps/api` | Standalone Nitro backend — Playwright and Gemini |
| `apps/web` | Nuxt 4 SPA, Vuetify 3 |
| `packages/shared` | Plain TypeScript, no build step |

The two apps are separate processes on separate ports and talk over HTTP, cross-origin. That
means `apps/web/.env` needs `NUXT_PUBLIC_API_BASE=http://localhost:8080` for local development
too, not only in production.

## Flow

1. Enter a URL and pick a category, or upload an image by hand
2. `POST /api/analyze` — screenshot and extraction in one call, with the image saved automatically
3. Results render immediately; there is no second button to press

## API docs

Generated by Nitro's built-in OpenAPI support — no extra dependency. With the API running:

| Path | What |
| --- | --- |
| `/docs` | Swagger UI |
| `/reference` | Scalar UI |
| `/openapi.json` | Raw spec |

Each route declares its own schema with `defineRouteMeta({ openAPI: {...} })`. It has to be a
literal object — Nitro's extractor walks the AST at build time, so a shared helper function
returning the same shape produces nothing. That is why the batch-search routes each repeat it.

Full request and response detail in [`apps/api/API.md`](./apps/api/API.md).

## Getting started

```bash
pnpm install   # apps/api's postinstall also runs `playwright install chromium`
pnpm dev       # api on :8080, web on :3000
```

| Command | What it does |
| --- | --- |
| `pnpm dev` | Both apps in parallel |
| `pnpm dev:api` | API only |
| `pnpm dev:web` | Web only |
| `pnpm build` | Build both |
| `pnpm preview` | Preview both builds |
| `pnpm build:pages` | Web only — Cloudflare Pages static build, no Playwright needed |

Either app can be run directly: `pnpm --filter poc-pricetrends-api dev`.
